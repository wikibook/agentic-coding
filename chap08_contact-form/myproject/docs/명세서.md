# 문의 폼 명세서

## 1. 개요

Laravel로 구축한 문의 폼 애플리케이션.
엔드유저가 이용하는 '문의 폼'과 관리자가 이용하는 '관리 페이지'의 두 기능으로 구성된다.

## 2. 기술 스택

| 항목 | 기술 |
|---|---|
| 프레임워크 | Laravel 12 |
| 언어 | PHP |
| 데이터베이스 | SQLite |
| CSS | 인라인 CSS(Vite/Tailwind 미사용) |
| 페이지네이션 | Bootstrap 5 스타일 |

## 3. 데이터베이스 설계

### contacts 테이블

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | bigint | PK, AUTO_INCREMENT | 자동 채번 |
| name | string(255) | NOT NULL | 이름 |
| email | string(255) | NOT NULL | 이메일 주소 |
| subject | string(255) | NOT NULL | 제목 |
| body | text | NOT NULL | 본문 |
| status | string(255) | NOT NULL, DEFAULT '신규' | 상태 |
| created_at | timestamp | NULLABLE | 작성 일시 |
| updated_at | timestamp | NULLABLE | 갱신 일시 |

### 상태의 종류

| 값 | 설명 |
|---|---|
| 신규 | 초기 상태(기본값) |
| 대응 중 | 대응을 시작한 상태 |
| 해결 완료 | 대응이 완료된 상태 |

## 4. 라우팅

### 문의 폼

| 메서드 | URL | 라우트명 | 처리 내용 |
|---|---|---|---|
| GET | `/` | contact.create | 입력 폼 표시 |
| POST | `/contact/confirm` | contact.confirm | 확인 화면 표시 |
| POST | `/contact` | contact.store | 전송 처리 |
| GET | `/contact/thanks` | contact.thanks | 완료 화면 표시 |

### 관리 페이지

| 메서드 | URL | 라우트명 | 처리 내용 |
|---|---|---|---|
| GET | `/admin/contacts` | admin.contacts.index | 목록 표시 |
| GET | `/admin/contacts/{contact}` | admin.contacts.show | 상세 표시 |
| PATCH | `/admin/contacts/{contact}` | admin.contacts.update | 상태 업데이트 |

## 5. 문의 폼 기능

### 5.1 화면 전환 흐름

```
입력 폼 → 확인 화면 → 전송 처리 → 완료 화면
                 ↓
              '뒤로' → 입력 폼(입력값 복원)
```

### 5.2 입력 폼(GET `/`)

입력 항목:

| 항목 | 입력 형식 | 필수 |
|---|---|---|
| 이름 | 텍스트 | 예 |
| 이메일 주소 | 메일 | 예 |
| 제목 | 텍스트 | 예 |
| 본문 | 텍스트 영역 | 예 |

- 확인 화면에서 '뒤로'로 이동한 경우, 세션에 저장된 입력값이 복원된다
- 유효성 검사 오류 시에는 `old()`로 입력값이 복원된다

### 5.3 유효성 검사 규칙

| 필드 | 규칙 | 오류 메시지 |
|---|---|---|
| name | required, string, max:255 | 이름을 입력해 주세요. / 이름은 255자 이내로 입력해 주세요. |
| email | required, email, max:255 | 이메일 주소를 입력해 주세요. / 올바른 이메일 주소 형식으로 입력해 주세요. / 이메일 주소는 255자 이내로 입력해 주세요. |
| subject | required, string, max:255 | 제목을 입력해 주세요. / 제목은 255자 이내로 입력해 주세요. |
| body | required, string | 본문을 입력해 주세요. |

### 5.4 확인 화면(POST `/contact/confirm`)

- 유효성 검사를 통과한 뒤 입력 데이터를 세션(키: `contact_data`)에 저장해 표시
- 표시 항목: 이름, 이메일 주소, 제목, 본문
- 조작 버튼:
  - **뒤로**: 입력 폼으로 리다이렉트(세션 데이터로 입력값 복원)
  - **전송**: 전송 처리로 POST

### 5.5 전송 처리(POST `/contact`)

- '뒤로' 버튼(`back` 파라미터)이 눌린 경우: 입력 폼으로 리다이렉트
- 세션에서 `contact_data`를 가져와 DB에 저장
- 저장 후 세션에서 `contact_data`를 삭제
- 세션이 끊긴 경우: 입력 폼으로 리다이렉트

### 5.6 완료 화면(GET `/contact/thanks`)

- '문의해 주셔서 감사합니다' 메시지를 표시
- '처음으로 돌아가기' 링크로 입력 폼으로 이동

## 6. 관리 페이지 기능

### 6.1 목록 표시(GET `/admin/contacts`)

- 문의를 최신순(`latest()`)으로 표시
- 페이지당 10건의 페이지네이션
- 표시 컬럼: ID, 이름, 제목, 상태, 수신 일시
- 이름을 클릭하면 상세 화면으로 이동
- 상태는 배지로 색을 나누어 표시:
  - 신규: 빨강(`#e74c3c`)
  - 대응 중: 주황(`#f39c12`)
  - 해결 완료: 초록(`#27ae60`)
- 데이터가 0건인 경우에는 '문의가 아직 없습니다.'를 표시

### 6.2 상세 표시(GET `/admin/contacts/{contact}`)

- 표시 항목: ID, 이름, 이메일 주소, 제목, 본문, 수신 일시
- 상태 변경용 드롭다운 리스트(신규 / 대응 중 / 해결 완료)
- '상태 업데이트' 버튼으로 업데이트 처리
- '목록으로 돌아가기' 링크
- 상태 업데이트 성공 시 플래시 메시지 '상태를 업데이트했습니다.'를 표시

### 6.3 상태 업데이트(PATCH `/admin/contacts/{contact}`)

- 유효성 검사: `status`가 `신규` / `대응 중` / `해결 완료` 중 하나일 것
- 업데이트 후 상세 화면으로 리다이렉트(성공 메시지 포함)

## 8. 보안 대책

| 대책 | 구현 방법 |
|---|---|
| CSRF 보호 | 모든 폼에 `@csrf` 디렉티브를 사용 |
| XSS 방지 | Blade의 `{{ }}`에 의한 자동 이스케이프, 본문의 줄바꿈 표시는 `{!! nl2br(e()) !!}`를 사용 |
| 데이터 변조 방지 | 확인 화면의 데이터는 세션 방식으로 보관(숨김 필드 미사용) |
| 매스 어사인먼트 방지 | 모델의 `$fillable`로 허용 컬럼을 명시적으로 지정 |

## 9. 인증

현재 관리 페이지에 인증 기능은 구현되어 있지 않다. `/admin/contacts`에 직접 접근하면 관리 기능을 이용할 수 있다.
