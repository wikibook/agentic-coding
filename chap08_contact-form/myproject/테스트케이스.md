# 테스트 케이스 목록

## 1. 문의 폼 쪽

### 1.1 입력 화면(GET /)

| No | 테스트 항목 | 조작 순서 | 기대 결과 |
|----|-----------|---------|---------|
| 1-1-1 | 화면 표시 | `/`에 접근한다 | 입력 폼(이름·이메일 주소·제목·본문)이 표시된다 |
| 1-1-2 | 필수 표시 | 입력 화면을 확인한다 | 각 항목에 필수 표시(*)가 있다 |

### 1.2 유효성 검사(POST /contact/confirm)

#### 필수 검사

| No | 테스트 항목 | 조작 순서 | 기대 결과 |

| 1-2-1 | 전체 항목 미입력 | 모두 빈칸인 채로 '확인 화면으로'를 누른다 | 전체 항목에 오류 메시지가 표시된다 |
| 1-2-2 | 이름 미입력 | 이름만 빈칸으로 전송한다 | '이름을 입력해 주세요.'가 표시된다 |
| 1-2-3 | 이메일 주소 미입력 | 이메일 주소만 빈칸으로 전송한다 | '이메일 주소를 입력해 주세요.'가 표시된다 |
| 1-2-4 | 제목 미입력 | 제목만 빈칸으로 전송한다 | '제목을 입력해 주세요.'가 표시된다 |
| 1-2-5 | 본문 미입력 | 본문만 빈칸으로 전송한다 | '본문을 입력해 주세요.'가 표시된다 |

### 1.3 확인 화면(POST /contact/confirm → 확인 화면 표시)

| No | 테스트 항목 | 조작 순서 | 기대 결과 |
|----|-----------|---------|---------|
| 1-3-1 | 확인 화면 표시 | 전체 항목을 올바르게 입력하고 '확인 화면으로'를 누른다 | 확인 화면에 입력 내용이 표시된다 |
| 1-3-2 | 이름 표시 | 확인 화면에서 이름 표시를 확인한다 | 입력한 이름이 올바르게 표시된다 |
| 1-3-3 | 이메일 주소 표시 | 확인 화면에서 이메일 주소 표시를 확인한다 | 입력한 이메일 주소가 올바르게 표시된다 |
| 1-3-4 | 제목 표시 | 확인 화면에서 제목 표시를 확인한다 | 입력한 제목이 올바르게 표시된다 |
| 1-3-5 | 본문 표시 | 확인 화면에서 본문 표시를 확인한다 | 입력한 본문이 올바르게 표시된다 |
| 1-3-6 | 본문 줄바꿈 유지 | 본문에 줄바꿈이 있는 문장을 입력해 확인 화면을 표시한다 | 줄바꿈이 반영된 상태로 표시된다 |
| 1-3-7 | HTML 이스케이프 | 이름에 `<script>alert('XSS')</script>`를 입력해 확인 화면을 표시한다 | HTML 태그가 이스케이프되어 스크립트가 실행되지 않는다 |
| 1-3-8 | '뒤로' 버튼 | 확인 화면에서 '뒤로' 버튼을 누른다 | 입력 화면으로 돌아가고 입력 내용이 복원되어 있다 |
| 1-3-9 | '전송' 버튼 | 확인 화면에서 '전송' 버튼을 누른다 | 전송 처리가 실행되고 완료 화면으로 리다이렉트된다 |

### 1.4 전송 처리·완료 화면(POST /contact → GET /contact/thanks)

| No | 테스트 항목 | 조작 순서 | 기대 결과 |
|----|-----------|---------|---------|
| 1-4-1 | 데이터 저장 | 확인 화면에서 전송한다 | contacts 테이블에 입력 데이터가 저장된다 |
| 1-4-2 | 상태 초깃값 | 확인 화면에서 전송한다 | 저장된 데이터의 상태가 '신규'다 |
| 1-4-3 | 완료 화면 표시 | 전송 후 완료 화면을 확인한다 | '문의해 주셔서 감사합니다'가 표시된다 |
| 1-4-4 | 폼 링크 | 완료 화면을 확인한다 | 문의 폼 링크가 표시된다 |
| 1-4-5 | 세션 비우기 | 전송 완료 후 브라우저의 뒤로 가기로 확인 화면에 돌아가려 한다 | 세션 데이터가 비워져 확인 화면이 다시 표시되지 않는다 |

### 1.5 CSRF 보호

| No | 테스트 항목 | 조작 순서 | 기대 결과 |
|----|-----------|---------|---------|
| 1-5-1 | CSRF 토큰 없이 확인 | CSRF 토큰 없이 POST /contact/confirm에 요청한다 | 419 오류(Page Expired)가 반환된다 |
| 1-5-2 | CSRF 토큰 없이 전송 | CSRF 토큰 없이 POST /contact에 요청한다 | 419 오류(Page Expired)가 반환된다 |

## 2. 관리 페이지 쪽

| 2-5-3 | '해결 완료'→'신규'로 변경 | 상태를 '신규'로 바꾸고 업데이트 버튼을 누른다 | 상태가 '신규'로 바뀌고 성공 메시지가 표시된다 |
| 2-5-4 | 성공 메시지 표시 | 상태를 업데이트한다 | '상태를 업데이트했습니다.'가 표시된다 |
| 2-5-5 | DB 반영 확인 | 상태를 업데이트한 뒤 목록 화면에서 확인한다 | 목록 화면에도 업데이트된 상태가 반영된다 |
| 2-5-6 | 잘못된 상태 값 | 잘못된 상태 값(예: `잘못된 값`)으로 PATCH 요청을 보낸다 | 유효성 검사 오류가 반환된다 |
