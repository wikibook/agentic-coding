# ToDo 앱 명세서

## 1. 개요

| 항목 | 내용 |
|------|------|
| 앱 이름 | ToDo 리스트 |
| 목적 | 브라우저에서 동작하는 단순한 작업 관리 앱 |
| 기술 스택 | HTML + CSS + JavaScript(단일 파일) |
| 외부 라이브러리 | Quill(리치 텍스트 에디터, CDN에서 읽어 들임) |
| 데이터 영속화 | localStorage |
| 서버 | 불필요(정적 파일만) |

## 2. 기술 요건

- **단일 HTML 파일**: CSS·JavaScript를 모두 인라인으로 작성한다
- **서버 불필요**: 브라우저에서 HTML 파일을 직접 열기만 하면 동작한다
- **데이터 영속화**: `localStorage`를 사용해 브라우저를 닫아도 데이터가 유지된다
- **리치 에디터**: Quill을 CDN에서 읽어 들여 상세란에 사용한다
- **반응형 대응**: 불필요(데스크톱 브라우저를 상정)

## 3. 데이터 구조

### 3.1 할 일 항목 스키마

```json
{
  "id": "string (UUID v4)",
  "title": "string (최대 100자)",
  "detail": "string (HTML 형식, Quill의 출력)",
  "dateType": "none | date | datetime",
  "deadline": "string | null (ISO 8601 형식)",
  "completed": "boolean",
  "createdAt": "string (ISO 8601 형식)"
}
```

| 필드 | 타입 | 설명 |
|-----------|------|------|
| `id` | string | UUID v4로 자동 생성. 고유 식별자 |
| `title` | string | 작업 제목. 최대 100자 |
| `detail` | string | 상세 내용. Quill이 출력하는 HTML 문자열. 일반 텍스트 기준 최대 2000자 |
| `dateType` | string | 일시의 종류. `"none"`=없음 / `"date"`=날짜만 / `"datetime"`=시각까지 |
| `deadline` | string \| null | 마감 일시. `dateType`이 `"none"`이면 `null` |
| `completed` | boolean | 완료 상태. `true`=완료 / `false`=미완료 |
| `createdAt` | string | 작성 일시. ISO 8601 형식 |

### 3.2 localStorage 키 설계

| 키 | 값 | 설명 |
|------|-----|------|
| `todo-app-items` | JSON 배열 | 할 일 항목의 배열 |

## 4. 메인 화면 사양

와이어프레임(main.jpg)을 따른다.

### 4.1 레이아웃 구성

```
┌──────────────────────────────────┐
│ ToDo 리스트                      │
│ [신규]                           │
│                                  │
│ [전체] [미완료] [완료됨]         │
│               [완료됨을 삭제]    │
│                                  │
│ ── 오늘 중 ─────────────────     │
│  제목  ○월○일○시○분  [완료]      │
│  제목  ○월○일○시○분  [완료]      │
│                                  │
│ ── 내일까지 ────────────────     │
│  제목  ○월○일○시○분  [완료]      │
│                                  │
│ ── 그 외 ───────────────────     │
│  제목  ○월○일○시○분  [완료]      │
│                                  │
└──────────────────────────────────┘
```

### 4.2 헤더

- 제목 'ToDo 리스트'를 표시
- **[신규] 버튼**: 클릭하면 상세 화면(모달)을 신규 등록 모드로 연다

### 4.3 탭(필터)

세 개의 탭으로 표시를 전환한다.

| 탭 | 표시 대상 |
|------|---------|
| 전체 | 모든 할 일 항목 |
| 미완료 | `completed === false`인 항목 |
| 완료됨 | `completed === true`인 항목 |

- 기본은 '전체'를 선택 상태로 둔다
- 선택된 탭은 시각적으로 구분한다(활성 스타일)

### 4.4 [완료됨을 삭제] 버튼

- 클릭하면 확인 대화상자를 표시한다. '완료된 할 일을 모두 삭제할까요?'
- 'OK'로 `completed === true`인 모든 항목을 삭제하고 localStorage를 갱신
- '취소'면 아무것도 하지 않는다

### 4.5 섹션 나누기

할 일 항목을 다음 세 섹션으로 분류해 표시한다.

| 섹션 | 조건 |
|-----------|------|
| 오늘 중 | `deadline`이 오늘 23:59:59 이전 |
| 내일까지 | `deadline`이 내일 23:59:59 이전(이면서 오늘 중이 아님) |
| 그 외 | 위에 해당하지 않음(`deadline`이 모레 이후이거나 `dateType === "none"`) |

- '오늘' '내일'은 현재 브라우저의 로컬 시각을 기준으로 판정한다
- 각 섹션에 항목이 없으면 그 섹션 자체를 표시하지 않는다

### 4.6 정렬 순서

각 섹션 안의 정렬 규칙은 다음과 같다.

1. `deadline`이 설정된 항목을 먼저 표시(`dateType !== "none"`)
2. `deadline` 오름차순(이른 순)
3. `deadline`이 같거나 `dateType === "none"`인 항목은 `createdAt` 오름차순(오래된 순)

### 4.7 각 행의 표시

각 할 일 항목은 한 행으로 다음을 표시한다.

| 요소 | 설명 |
|------|------|
| 제목 | 작업 이름을 표시. 클릭하면 상세 화면을 편집 모드로 연다 |
| 일시 | `dateType`에 따른 표시(뒤에서 설명) |
| [완료] 버튼 | 클릭하면 `completed`를 토글 |

#### 일시의 표시 형식

| `dateType` | 표시 |
|-----------|------|
| `none` | 표시 없음 |
| `date` | `○월 ○일` |
| `datetime` | `○월 ○일 ○시 ○분` |

#### 완료 상태의 표시

- 미완료: [완료] 버튼을 표시
- 완료됨: 버튼 스타일을 바꾸고(예: 회색 처리, 취소선 등) 클릭하면 미완료로 되돌릴 수 있다

## 5. 상세 화면 사양(모달 팝업)

와이어프레임(detail.jpg)을 따른다.

### 5.1 레이아웃 구성

```
┌──────────────────────────────────┐
│                                  │
│  제목 [________________]         │
│                                  │
│  일시     ○ 없음                 │
│           ○ 날짜만  [연월일]     │
│           ○ 시각까지 [연월일시분]│
│                                  │
│  상세     ┌────────────────┐     │
│           │ Quill 에디터    │     │
│           │                │     │
│           └────────────────┘     │
│                                  │
│  [저장]  [취소]                  │
│                                  │
└──────────────────────────────────┘
```

### 5.2 모달 동작

- 배경을 오버레이로 어둡게 한다
- 모달 밖 클릭으로는 닫히지 않는다(명시적으로 [취소]를 눌러야 한다)
- ESC 키는 [취소]와 같은 동작

### 5.3 제목 입력

- 텍스트 입력 필드
- 최대 100자
- 필수 항목(빈칸이면 저장 불가)
- 자리표시자: '제목을 입력'

### 5.4 일시 선택

라디오 버튼 세 가지 중 선택한다.

| 선택지 | 동작 |
|--------|------|
| 없음 | 일시 입력란을 표시하지 않음 |
| 날짜만 | 날짜 입력란(`type="date"`)을 표시 |
| 시각까지 | 일시 입력란(`type="datetime-local"`)을 표시 |

- 기본은 '없음'을 선택
- 라디오 버튼을 바꾸면 입력란의 표시 여부를 즉시 반영

### 5.5 상세 입력(Quill 에디터)

- Quill 리치 텍스트 에디터를 사용
- 툴바: 굵게, 기울임, 밑줄, 목록(글머리 기호·번호 매기기)
- 일반 텍스트 기준 최대 2000자
- 선택 항목(빈칸이어도 저장 가능)

### 5.6 버튼

| 버튼 | 동작 |
|--------|------|
| [저장] | 유효성 검사 후 데이터를 저장하고 모달을 닫는다 |
| [취소] | 변경을 버리고 모달을 닫는다 |

### 5.7 신규 등록·편집 공용

| 모드 | 동작 |
|--------|------|
| 신규 등록 | 모든 필드를 빈칸으로 연다. 저장할 때 새 항목을 추가 |
| 편집 | 기존 데이터를 필드에 반영해 연다. 저장할 때 해당 항목을 갱신 |

## 6. 동작 사양 상세

### 6.1 '오늘 중' '내일까지'의 경계 로직

```
현재 시각: now
오늘의 끝: today 23:59:59.999
내일의 끝: tomorrow 23:59:59.999

오늘 중:   deadline <= 오늘의 끝
내일까지: 오늘의 끝 < deadline <= 내일의 끝
그 외:    deadline > 내일의 끝 OR deadline === null
```

- `dateType === "date"`이면 `deadline`은 지정일의 `00:00:00`으로 다룬다
  - 예: '3월 15일' 지정 → `2026-03-15T00:00:00` → 3월 14일 시점에는 '내일까지', 3월 15일 시점에는 '오늘 중'

### 6.2 완료 흐름

1. 메인 화면에서 [완료] 버튼을 클릭
2. `completed`를 `true`로 갱신
3. localStorage에 저장
4. 화면을 다시 그린다(탭에 따라 필터링)

### 6.3 완료 항목을 미완료로 되돌리기

1. 완료 항목의 [완료] 버튼(토글)을 클릭
2. `completed`를 `false`로 갱신
3. localStorage에 저장
4. 화면을 다시 그린다

### 6.4 삭제 흐름

- 개별 삭제 기능은 없다
- [완료됨을 삭제] 버튼으로 완료 항목을 일괄 삭제하는 것만 가능

### 6.5 유효성 검사

저장할 때 다음을 검사한다.

| 검사 항목 | 조건 | 오류 메시지 |
|------------|------|----------------|
| 제목 필수 | 빈 문자열 또는 공백만 | '제목을 입력해 주세요' |
| 제목 글자 수 | 101자 이상 | '제목은 100자 이내로 입력해 주세요' |
| 상세 글자 수 | 일반 텍스트 2001자 이상 | '상세는 2000자 이내로 입력해 주세요' |
| 날짜 필수 | `dateType`이 `date` 또는 `datetime`인데 날짜 미입력 | '일시를 입력해 주세요' |

- 오류 메시지는 해당 필드 근처에 빨간 글씨로 표시
