# ToDo 앱 테스트 케이스

## 테스트 실시 방법

- 브라우저로 `index.html`을 직접 열어 수동 테스트를 한다
- 각 테스트 케이스를 실시하기 전에, 따로 적지 않은 한 localStorage를 비워 초기 상태로 만든다
- '현재 일시'에 의존하는 테스트는 테스트 실시일에 맞춰 기댓값을 바꿔 읽는다

---

## 1. 초기 표시

### TC-1.1: 초기 상태의 화면 표시

- **전제**: localStorage에 데이터 없음
- **절차**: index.html을 연다
- **기대 결과**:
  - 제목 'ToDo 리스트'이 표시된다
  - [신규] 버튼이 표시된다
  - 탭 '전체' '미완료' '완료됨'이 표시된다
  - '전체' 탭이 활성 상태다(시각적으로 구분된다)
  - [완료됨을 삭제] 버튼이 표시된다
  - 섹션(오늘 중·내일까지·그 외)은 표시되지 않는다(항목이 없으므로)

### TC-1.2: 기존 데이터 읽어 들이기

- **전제**: localStorage에 다음 데이터를 수동으로 설정
  ```json
  [{"id":"test-1","title":"테스트 작업","detail":"","dateType":"none","deadline":null,"completed":false,"createdAt":"2026-03-14T00:00:00"}]
  ```
- **절차**: index.html을 연다
- **기대 결과**:
  - '테스트 작업'이 '그 외' 섹션에 표시된다

---

## 2. 상세 화면(모달) - 신규 등록

### TC-2.1: 모달 표시

- **절차**: [신규] 버튼을 클릭
- **기대 결과**:
  - 모달이 표시된다
  - 배경이 오버레이로 어두워진다
  - 제목 입력란이 비어 있고 자리표시자 '제목을 입력'이 표시된다
  - 일시 라디오 버튼 '없음'이 선택되어 있다
  - 날짜 입력란은 표시되지 않음
  - Quill 에디터가 표시되고 내용은 비어 있음
  - [저장] 버튼과 [취소] 버튼이 표시된다

### TC-2.2: 모달 밖 클릭

- **전제**: 모달이 표시되어 있음
- **절차**: 모달의 바깥쪽(오버레이 부분)을 클릭
- **기대 결과**: 모달이 닫히지 않는다

### TC-2.3: ESC 키로 닫기

- **전제**: 모달이 표시되어 있음
- **절차**: ESC 키를 누른다
- **기대 결과**: 모달이 닫힌다(취소와 같은 동작)

### TC-2.4: [취소] 버튼

- **전제**: 모달에서 제목에 '테스트'를 입력한 상태
- **절차**: [취소] 버튼을 클릭
- **기대 결과**:
  - 모달이 닫힌다
  - 메인 화면에 항목이 추가되지 않았다

---

## 3. 일시 선택

### TC-3.1: 라디오 버튼 '없음' 선택

- **전제**: 모달이 표시되어 있음
- **절차**: 일시 라디오 버튼 '없음'을 선택
- **기대 결과**: 날짜 입력란이 표시되지 않음

### TC-3.2: 라디오 버튼 '날짜만' 선택

- **전제**: 모달이 표시되어 있음
- **절차**: 일시 라디오 버튼 '날짜만'을 선택
- **기대 결과**: 날짜 입력란(type="date")이 표시된다

### TC-3.3: 라디오 버튼 '시각까지' 선택

- **전제**: 모달이 표시되어 있음
- **절차**: 일시 라디오 버튼 '시각까지'를 선택
- **기대 결과**: 일시 입력란(type="datetime-local")이 표시된다

### TC-3.4: 라디오 버튼 전환

- **전제**: 모달에서 '시각까지'를 선택하고 일시를 입력한 상태
- **절차**: '없음'으로 전환 → '날짜만'으로 전환
- **기대 결과**: 전환할 때마다 표시 여부가 즉시 반영된다

---

## 4. 유효성 검사

### TC-4.1: 제목 미입력으로 저장

- **전제**: 모달이 표시되어 있음
- **절차**: 제목을 빈칸인 채로 [저장]을 클릭
- **기대 결과**: '제목을 입력해 주세요'가 빨간 글씨로 제목 입력란 근처에 표시된다

### TC-4.2: 제목이 공백만인 상태로 저장

- **전제**: 모달이 표시되어 있음
- **절차**: 제목에 공백만 입력하고 [저장]을 클릭
- **기대 결과**: '제목을 입력해 주세요'가 빨간 글씨로 표시된다

### TC-4.3: 제목 101자로 저장

- **전제**: 모달이 표시되어 있음
- **절차**: 제목에 101자를 입력하고 [저장]을 클릭
- **기대 결과**: '제목은 100자 이내로 입력해 주세요'가 빨간 글씨로 표시된다

### TC-4.4: 제목 100자로 저장

- **전제**: 모달이 표시되어 있음
- **절차**: 제목에 정확히 100자를 입력하고 [저장]을 클릭
- **기대 결과**: 유효성 검사 오류 없이 정상적으로 저장된다

### TC-4.5: 상세 2001자로 저장

- **전제**: 모달이 표시되어 있음
- **절차**: 제목을 입력하고 Quill 에디터에 일반 텍스트로 2001자를 입력한 뒤 [저장]을 클릭
- **기대 결과**: '상세는 2000자 이내로 입력해 주세요'가 빨간 글씨로 표시된다

### TC-4.6: 상세 2000자로 저장

- **전제**: 모달이 표시되어 있음
- **절차**: 제목을 입력하고 Quill 에디터에 일반 텍스트로 정확히 2000자를 입력한 뒤 [저장]을 클릭
- **기대 결과**: 유효성 검사 오류 없이 정상적으로 저장된다

### TC-4.7: 일시 '날짜만'인데 날짜 미입력

- **전제**: 모달이 표시되어 있음
- **절차**: 제목을 입력하고 일시 '날짜만'을 선택한 뒤 날짜를 입력하지 않고 [저장]을 클릭
- **기대 결과**: '일시를 입력해 주세요'가 빨간 글씨로 표시된다

### TC-4.8: 일시 '시각까지'인데 일시 미입력

- **전제**: 모달이 표시되어 있음
- **절차**: 제목을 입력하고 일시 '시각까지'를 선택한 뒤 일시를 입력하지 않고 [저장]을 클릭
- **기대 결과**: '일시를 입력해 주세요'가 빨간 글씨로 표시된다

## 5. 신규 등록(정상 케이스)

### TC-5.1: 최소 구성으로 저장(제목만)

- **절차**:
  1. [신규]를 클릭
  2. 제목에 '장보기 목록'을 입력
  3. 일시는 '없음'인 채로 둔다
  4. [저장]을 클릭
- **기대 결과**:
  - 모달이 닫힌다
  - 메인 화면의 '그 외' 섹션에 '장보기 목록'이 표시된다
  - 일시 표시 없음
  - [완료] 버튼이 표시된다
  - localStorage에 올바른 형식으로 데이터가 저장되어 있다(id가 UUID, completed가 false, dateType이 "none", deadline이 null)

### TC-5.2: 날짜를 넣어 저장

- **절차**:
  1. [신규]를 클릭
  2. 제목에 '보고서 제출'을 입력
  3. 일시 '날짜만'을 선택하고 오늘 날짜를 입력
  4. [저장]을 클릭
- **기대 결과**:
  - '오늘 중' 섹션에 '보고서 제출'이 표시된다
  - 일시가 '○월 ○일' 형식으로 표시된다
  - localStorage의 dateType이 "date"

### TC-5.3: 일시를 넣어 저장

- **절차**:
  1. [신규]를 클릭
  2. 제목에 '회의'를 입력
  3. 일시 '시각까지'를 선택하고 오늘 일시를 입력
  4. [저장]을 클릭
- **기대 결과**:
  - '오늘 중' 섹션에 '회의'가 표시된다
  - 일시가 '○월 ○일 ○시 ○분' 형식으로 표시된다
  - localStorage의 dateType이 "datetime"

### TC-5.4: 상세를 넣어 저장

- **절차**:
  1. [신규]를 클릭
  2. 제목에 '기획서 작성'을 입력
  3. Quill 에디터에서 굵게·글머리 기호 등을 써서 상세를 입력
  4. [저장]을 클릭
- **기대 결과**:
  - 정상적으로 저장된다
  - localStorage의 detail에 HTML 형식으로 저장되어 있다

## 6. 편집

### TC-6.1: 편집 모드로 열기

- **전제**: '장보기 목록'이라는 항목이 등록되어 있음
- **절차**: 메인 화면에서 '장보기 목록'의 제목을 클릭
- **기대 결과**:
  - 모달이 편집 모드로 열린다
  - 제목란에 '장보기 목록'이 표시되어 있다
  - 일시 라디오 버튼이 등록 당시의 선택 상태
  - Quill 에디터에 등록 당시의 상세 내용이 표시되어 있다

### TC-6.2: 제목을 편집해 저장

- **전제**: '장보기 목록'이라는 항목이 등록되어 있음
- **절차**:
  1. '장보기 목록'의 제목을 클릭
  2. 제목을 '장보기 목록(수정)'으로 변경
  3. [저장]을 클릭
- **기대 결과**:
  - 모달이 닫힌다
  - 메인 화면에 '장보기 목록(수정)'이 표시된다
  - id는 바뀌지 않았다(같은 항목이 갱신되었다)

### TC-6.3: 일시를 바꿔 저장

- **전제**: dateType이 "none"인 항목이 등록되어 있음
- **절차**:
  1. 항목의 제목을 클릭해 편집 모드로 연다
  2. 일시를 '날짜만'으로 바꾸고 내일 날짜를 입력
  3. [저장]을 클릭
- **기대 결과**:
  - '내일까지' 섹션으로 옮겨져 표시된다
  - 일시가 '○월 ○일' 형식으로 표시된다

### TC-6.4: 상세를 편집해 저장

- **전제**: 상세가 입력된 항목이 등록되어 있음
- **절차**:
  1. 항목의 제목을 클릭
  2. Quill 에디터에서 상세를 변경
  3. [저장]을 클릭
- **기대 결과**: localStorage의 detail이 갱신되어 있다

### TC-6.5: 편집을 취소

- **전제**: '장보기 목록'이라는 항목이 등록되어 있음
- **절차**:
  1. '장보기 목록'의 제목을 클릭
  2. 제목을 '변경 후 제목'으로 고쳐 쓴다
  3. [취소]를 클릭
- **기대 결과**:
  - 모달이 닫힌다
  - 메인 화면에 '장보기 목록' 그대로 표시된다(바뀌지 않았다)

---

## 7. 완료/미완료 토글

### TC-7.1: 미완료 → 완료

- **전제**: 미완료 항목 '작업A'가 등록되어 있음
- **절차**: '작업A'의 [완료] 버튼을 클릭
- **기대 결과**:
  - 항목이 완료 상태 표시로 바뀐다(회색 처리, 취소선 등)
  - localStorage의 completed가 true로 갱신되어 있다

### TC-7.2: 완료 → 미완료

- **전제**: 완료된 항목 '작업A'가 있음
- **절차**: '작업A'의 완료 버튼(토글)을 클릭
- **기대 결과**:
  - 항목이 미완료 상태 표시로 돌아간다
  - [완료] 버튼이 원래 스타일로 돌아간다
  - localStorage의 completed가 false로 갱신되어 있다

## 8. 탭(필터)

### TC-8.1: '전체' 탭

- **전제**: 미완료 2건, 완료 1건의 항목이 있음
- **절차**: '전체' 탭을 클릭
- **기대 결과**: 전체 3건이 표시된다

### TC-8.2: '미완료' 탭

- **전제**: 미완료 2건, 완료 1건의 항목이 있음
- **절차**: '미완료' 탭을 클릭
- **기대 결과**:
  - 미완료 2건만 표시된다
  - 탭이 시각적으로 활성 상태

### TC-8.3: '완료됨' 탭

- **전제**: 미완료 2건, 완료 1건의 항목이 있음
- **절차**: '완료됨' 탭을 클릭
- **기대 결과**:
  - 완료 1건만 표시된다
  - 탭이 시각적으로 활성 상태

### TC-8.4: 탭 전환 후의 완료 토글

- **전제**: '완료됨' 탭을 선택 중
- **절차**: 항목의 완료 토글을 클릭
- **기대 결과**: '완료됨' 탭이 활성인 채로 화면이 다시 그려진다

## 9. [완료됨을 삭제]

### TC-9.1: 확인 대화상자에서 OK

- **전제**: 완료 항목이 2건, 미완료 항목이 1건 있음
- **절차**: [완료됨을 삭제] 버튼을 클릭 → 확인 대화상자에서 'OK'
- **기대 결과**:
  - 완료 2건이 삭제된다
  - 미완료 1건은 남는다
  - localStorage가 갱신되어 있다

### TC-9.2: 확인 대화상자에서 취소

- **전제**: 완료 항목이 있음
- **절차**: [완료됨을 삭제] 버튼을 클릭 → 확인 대화상자에서 '취소'
- **기대 결과**: 아무것도 삭제되지 않는다

### TC-9.3: 완료 항목이 없는 상태로 삭제

- **전제**: 미완료 항목만 있음
- **절차**: [완료됨을 삭제] 버튼을 클릭 → 'OK'
- **기대 결과**: 항목은 바뀌지 않는다(미완료 항목은 삭제되지 않는다)

## 10. 섹션 나누기

### TC-10.1: '오늘 중' 섹션

- **절차**: deadline이 오늘 날짜인 항목을 등록
- **기대 결과**: '오늘 중' 섹션에 표시된다

### TC-10.2: '내일까지' 섹션

- **절차**: deadline이 내일 날짜인 항목을 등록
- **기대 결과**: '내일까지' 섹션에 표시된다

### TC-10.3: '그 외' 섹션 - 모레 이후

- **절차**: deadline이 모레 이후인 항목을 등록
- **기대 결과**: '그 외' 섹션에 표시된다

### TC-10.4: '그 외' 섹션 - 일시 없음

- **절차**: dateType이 "none"인 항목을 등록
- **기대 결과**: '그 외' 섹션에 표시된다

### TC-10.5: 빈 섹션 숨기기

- **전제**: '오늘 중'에 해당하는 항목이 없음
- **기대 결과**: '오늘 중' 섹션 제목 자체가 표시되지 않는다

### TC-10.6: dateType "date"의 경계 판정

- **절차**: 일시 '날짜만'으로 내일 날짜를 지정해 항목을 등록
- **기대 결과**:
  - 등록일(오늘): deadline은 내일 00:00:00 → '내일까지' 섹션에 표시
  - 다음 날이 되면 '오늘 중' 섹션에 표시된다

## 11. 정렬 순서

### TC-11.1: deadline 있음 → 없음 순서

- **전제**: 같은 섹션 안에 deadline이 있는 항목과 없는(dateType="none") 항목이 있음
- **기대 결과**: deadline이 있는 항목이 먼저 표시된다

### TC-11.2: deadline 오름차순

- **전제**: 같은 섹션 안에 deadline이 다른 2건의 항목(이른 쪽과 늦은 쪽)
- **기대 결과**: deadline이 이른 쪽이 먼저 표시된다

### TC-11.3: deadline이 같으면 createdAt 오름차순

- **전제**: 같은 섹션 안에 deadline이 같고 createdAt이 다른 2건
- **기대 결과**: createdAt이 오래된 쪽이 먼저 표시된다

### TC-11.4: deadline이 없는 것끼리는 createdAt 오름차순

- **전제**: dateType="none"인 항목이 여러 건(createdAt이 다름)
- **기대 결과**: createdAt이 오래된 순으로 표시된다

- **기대 결과**: Quill 에디터에 굵게·글머리 기호 서식이 올바르게 복원되어 있다

## 14. 데이터 영속화(localStorage)

### TC-14.1: 저장 후 새로고침

- **절차**:
  1. 항목을 3건 등록
  2. 브라우저를 새로고침(F5)
- **기대 결과**: 3건 모두 올바르게 표시된다

### TC-14.2: 완료 상태의 새로고침

- **절차**:
  1. 항목을 완료로 만든다
  2. 브라우저를 새로고침
- **기대 결과**: 완료 상태가 유지되어 있다

### TC-14.3: 삭제 후 새로고침

- **절차**:
  1. 완료 항목을 삭제
  2. 브라우저를 새로고침
- **기대 결과**: 삭제된 항목은 되살아나지 않는다

### TC-14.4: 데이터 형식 확인

- **절차**: 항목을 등록한 뒤 개발자 도구에서 localStorage의 `todo-app-items`를 확인
- **기대 결과**:
  - JSON 배열로 올바르게 파싱된다
  - 각 항목에 id, title, detail, dateType, deadline, completed, createdAt이 들어 있다
  - id는 UUID v4 형식
  - createdAt은 ISO 8601 형식

## 15. 복합 시나리오

### TC-15.1: 전체 기능을 거치는 E2E 테스트

- **절차**:
  1. 초기 상태(데이터 없음)로 연다 → 항목이 없음을 확인
  2. [신규]로 항목A(오늘, 시각까지)를 등록 → '오늘 중'에 표시
  3. [신규]로 항목B(내일, 날짜만)를 등록 → '내일까지'에 표시
  4. [신규]로 항목C(일시 없음)를 등록 → '그 외'에 표시
  5. '미완료' 탭 → 3건 표시
  6. 항목A를 완료로 만든다 → 표시가 회색 처리 등으로 바뀜
  7. '완료됨' 탭 → 항목A만 표시
  8. '미완료' 탭 → 항목B, C만 표시
  9. 항목B의 제목을 클릭해 편집 → 제목을 바꿔 저장
  10. [완료됨을 삭제] → 확인 대화상자 → OK → 항목A가 삭제된다
  11. '전체' 탭 → 항목B(변경 후), C 2건이 표시
  12. 새로고침 → 같은 상태가 유지된다

### TC-15.2: 대량 데이터

- **절차**: 50건의 항목을 등록(오늘 중, 내일까지, 그 외을 섞어서)
- **기대 결과**:
  - 각 섹션에 올바르게 분류된다
  - 정렬 순서가 올바르다
  - 화면 조작이 답답하지 않다

## 16. 오류 케이스·경곗값

### TC-16.1: localStorage가 비어 있는 경우

- **전제**: localStorage에 `todo-app-items` 키가 없음
- **기대 결과**: 오류 없이 빈 목록으로 표시된다

### TC-16.2: localStorage에 잘못된 데이터

- **전제**: localStorage의 `todo-app-items`에 잘못된 JSON 문자열을 설정
- **기대 결과**: 앱이 죽지 않고 빈 목록으로 표시된다(또는 오류 처리가 이뤄진다)

### TC-16.3: 제목의 경곗값(1자)

- **절차**: 제목에 1자만 입력해 저장
- **기대 결과**: 정상적으로 저장된다

### TC-16.4: 상세가 비어 있는 채로 저장

- **절차**: 제목만 입력하고 상세는 빈 채로 저장
- **기대 결과**: 정상적으로 저장된다(상세는 선택 항목)
